## 2025-02-18 - XSS Bypass via Control Characters in URI Schemes
**Vulnerability:** A subtle XSS bypass existed in the `safeHref` URL sanitization function. The function used the regex `^[a-z][a-z0-9+.-]*:` to detect URL schemes. An attacker could bypass this by inserting C0 control characters (like `\x00` null byte or `\x09` tab) into the scheme (e.g., `java\x00script:alert(1)`), causing the regex to fail and the URL to be treated as a safe relative path. When the browser later parses the href in an `<a>` tag, it strips control characters, executing the malicious payload.
**Learning:** Browsers have robust parser differentials compared to standard regex implementations. Browsers silently strip control characters and whitespace from URLs during HTML parsing, meaning standard scheme validation logic can easily be bypassed if the input is not pre-cleaned of these characters.
**Prevention:** Always strip ASCII control characters (`[\u0000-\u001f\u007f]`) from user-supplied URLs *before* performing scheme validation to ensure the validation regex operates on the same string the browser will ultimately parse. Note: Do this *after* `.trim()` to avoid blocking legitimate whitespace.
